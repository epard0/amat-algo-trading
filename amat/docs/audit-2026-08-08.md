# AMAT Repository Audit — Verified Findings

Scope: implemented code only (`src/amat/**`, `configs/**`, `tests/**`, `.claude/scripts/**`, `pyproject.toml`). Every finding below survived an adversarial verification pass; severities are the **corrected** ones, not the originally claimed ones. Overlapping claims have been merged (33 raw claims → 24 findings).

A structural caveat applies to almost everything here: the strategy core is unimplemented, so **none of these defects can currently produce a wrong number**. They are latent defects in the foundation layer — validation models, domain records, provenance, and gates — that will become live the moment the core is written. That is precisely why they are worth fixing now, while the fixes are one-liners.

---

## High

### 1. `src/amat/domain/fills.py:84` — enum identity comparison silently inverts every buy
`return self.quantity if self.side is Side.BUY else -self.quantity`. `__post_init__` (fills.py:65-79) validates `quantity`, `price`, and `cost_cash` but never `side`. Because sign selection uses `is` against a `StrEnum`, a plain `str` side passes construction and takes the `SELL` branch.

Verified by execution: `Fill(side='buy', quantity=Decimal('10'), price=Decimal('100'), cost_cash=Decimal('1'))` yields `signed_quantity = -10` and `cash_delta = +999`; correct values are `+10` and `-1001`. `side == Side.BUY` is `True` while `side is Side.BUY` is `False`, so equality-based debugging will not reveal it. `SimulatedOrder.signed_quantity` (orders.py:101) and `Fill.cash_delta` (fills.py:99) have the identical defect.

Why it matters: a $2,000 cash error and an inverted position per fill, with no exception raised, and `reconcile_session` still passes because the error is inside the fill rather than between snapshots. The trigger is any deserialization path that yields string sides — exactly what `amat.data` and the NautilusTrader adapter will introduce.

Fix: in `__post_init__`, coerce on the frozen dataclass — `object.__setattr__(self, "side", Side(self.side))` — or `isinstance`-check and raise `ConfigurationError`. Independently, replace `is Side.BUY` with `== Side.BUY` at fills.py:84, fills.py:99, orders.py:101.

## Medium

### 2. `src/amat/boundaries.py:87` — `ExecutionBoundary.execute` cannot compute the contract's fill price
The signature takes `execution_bars: Mapping[Symbol, DailyBar]`. `strategy-contract.md:76` requires the next session's **09:30–09:35 America/New_York raw-price VWAP**; `configs/data/sources.toml:36` declares an intraday source for exactly that purpose; and no intraday record type exists anywhere in `src/amat/domain/` (grep for `intraday|minute` matches only a docstring). VWAP is not derivable from OHLC+volume under any reading of `DailyBar`.

Consequently `ExecutionConfig.price_method: Literal["vwap"]` (models.py:238) is **unsatisfiable by any conforming implementation**. An implementer is forced to price at `raw_open` — which `validation-protocol.md:41` lists as a robustness *sensitivity*, not the canonical fill. Related: `DailyBar.is_tradable` (bars.py:113-120) gates on whole-session volume, so a symbol with zero volume in the execution window but non-zero session volume yields a `Fill` where `MissedFillReason.ZERO_VOLUME` is contractually required — a guardrail-9 silent fallback.

Fix: introduce an intraday/window bar record (or a `window_vwap` + `window_volume` field), change the `execute` signature to accept it, and derive `is_tradable` from window volume.

### 3. `src/amat/boundaries.py:95` — `AccountingBoundary.advance` has no corporate-actions input
`architecture.md:44` defines the boundary as "prior ledger, fills, **actions**, and marks enter". The class docstring at boundaries.py:93 repeats that sentence verbatim; the signature two lines later takes only `(previous, session, fills, marks)`.

`fills` cannot absorb actions: `Fill.__post_init__` requires strictly positive quantity *and* price, and `cash_delta` always returns ±(quantity × price) — a cash dividend (cash, no shares) and a 2-for-1 split (shares, no cash) are both unrepresentable. On a split, `advance` receives a halved mark and unchanged quantities, so equity halves and `reconcile_session` raises `AccountingError`. On an ex-dividend session, `PeriodAttribution.distributions` can only ever be `Decimal(0)`. Same argument applies to `PeriodAttribution.cash_yield`: no cash-rate or day-count input exists either.

> **Correction, 2026-08-10.** The sentence "equity halves and `reconcile_session` raises `AccountingError`" is **wrong**, and the error was consequential: it made a silent corruption sound like a loud one, which is part of why the actions input was later added to `run_backtest` and then left unsupplied by every caller for two years. Measured directly — a 1,000-share position across a 2:1 split with no action supplied: equity fell 102,220.00 → 55,920.00, the full 46,300.00 was booked as `market_pnl`, and the reconciliation residual was exactly **0.00**. No exception. `market_pnl` is *computed* as `closing value − opening value − traded notional`, so it absorbs any mark movement by construction; the identity proves cash and shares are accounted for, not that a price step had a cause. Everything else in this finding stands, and the recommended fix was the right one. The same false claim was propagated into the docstrings of `boundaries.py` and `backtest/accounting.py`; both have been corrected.

Fix: add a `CorporateAction` domain record (architecture.md places actions under `src/amat/data/`), add `actions` and a cash-rate input to `advance`, and reconcile the docstring with the signature.

### 4. `src/amat/provenance.py:167` — `detect_code_revision` records a foreign repository's commit
`subprocess.run(["git","rev-parse","HEAD"], cwd=workdir)` with no `--show-toplevel` comparison. Git's upward repo discovery means a directory that is *not* a repository reports the enclosing repo's commit.

Verified: a repo at `$TMPDIR/gt9` with a plain subdirectory `gt9/sub` → `detect_code_revision("$TMPDIR/gt9/sub")` returns `detected=True, dirty=False, is_promotable=True` naming a foreign tree. The docstring's promise (provenance.py:162-166) that absence of a repository "is never silently reported as clean" is false. `git status --porcelain` (provenance.py:185) has the same scoping bug, so `dirty` describes the wrong worktree.

Fix: compare `git rev-parse --show-toplevel` against `workdir`; return `detected=False` with a reason on mismatch. Scope both subprocess calls identically.

### 5. `src/amat/provenance.py:92` — a manifest naming zero inputs validates as `passed`
Verified: `RunManifest(..., code_revision=CodeRevision(detected=False, reason='no git'), validation_status='passed')` constructs with `datasets=()` and `dependency_lock_sha256=None`. The only cross-field validator, `_require_consistent_status` (provenance.py:135-149), checks `failed_gates` and `holdout_accessed` and nothing else.

This contradicts the module's own docstring (provenance.py:3-5: "each one is required, and each absence is recorded explicitly rather than defaulted away") — `CodeRevision` forces a `reason` on failure, but `datasets` and `dependency_lock_sha256` are simply defaulted away. `promotion-gates.md:13` ("Every report traces to a run manifest and immutable inputs") is unenforceable against such a manifest. (`random_seeds=()` is *not* part of this defect — a fully deterministic run legitimately draws none.)

Fix: add a model validator requiring `validation_status == "passed"` to imply non-empty `datasets`, a non-`None` `dependency_lock_sha256`, and `code_revision.detected is True`.

### 6. `src/amat/config/models.py:331` — warm-up validator permits far less than the mandated 252 sessions
`required = max(trend.max_horizon_sessions, covariance.lookback_sessions, volatility.min_periods_sessions)` — there is no absolute floor. `strategy-contract.md:14` requires "252 completed valid sessions plus enough history for the covariance estimator", and models.py:7-9 explicitly states the reference wins if the two disagree.

Verified: `StrategyConfig(name="amat-etf", version="1.0.0", trend=TrendConfig(horizons_sessions=(5,)), warmup=WarmupConfig(min_completed_sessions=120))` is accepted. Since `covariance.lookback_sessions` is also configurable, the effective floor collapses to `volatility.min_periods_sessions = 60`. `name` and `version` are free-form strings, so an off-contract config can still be labelled `amat-etf v1.0.0`. Root cause: `horizons_sessions` (models.py:154) is unpinned — only "strictly increasing and unique".

(The claimed `<` vs `<=` off-by-one is **not** a defect: 252 warm-up sessions plus decision session *t* gives 253 closes, enough for `ln(P[t]/P[t-252])`.)

Fix: pin `horizons_sessions` to `(21, 63, 252)` for v1 and add an absolute `min_completed_sessions >= 252` floor, matching the module's existing style (`Literal[False]`, `ge=1`, `_require_primary_is_constant_zero`).

### 7. `src/amat/config/models.py:261` — zero-cost runs are indistinguishable from canonical runs
`baseline_one_way_bps: NonNegativeFloat = 2.0` admits `0.0`. Verified: `CostConfig(baseline_one_way_bps=0.0, stress_one_way_bps=(1.0,))` is accepted — `_require_upward_stress` is satisfied by any positive stress entry. No field records diagnostic status, so a frictionless backtest resolves to a config (and therefore a manifest) indistinguishable from the canonical 2 bps run. CLAUDE.md guardrail 7 says zero-cost runs are diagnostic only; `configs/strategy/amat_v1.toml:167` states the rule as a comment the schema does not enforce.

Note the module already solves this exact problem elsewhere: `CashConfig` uses an `is_primary` flag plus `_require_primary_is_constant_zero` (models.py:283-303).

Fix: mirror `CashConfig` — add `is_primary: bool` to `CostConfig` and reject `is_primary and baseline_one_way_bps <= 0`.

### 8. `src/amat/config/models.py:126` — the volatility floor can be switched off
`floor_annualized: NonNegativeFloat = 0.05` accepts `0.0`. `strategy-contract.md:30` defines `sigma = max(sigma20, 0.75*sigma60, 0.05)` where `0.05` is a hard floor, not a tunable. With the floor at zero, `q[i] = long_score[i]/sigma[i]` (contract:49) diverges for any low-volatility symbol and the symbol/cluster caps silently truncate the result — the volatility target becomes meaningless rather than failing closed.

This is the outlier in a file that bounds everything else: `target_annualized_volatility` is `Field(gt=0.0, le=1.0)` (models.py:209).

(The `slow_weight` half of this claim is **refuted** — since sigma is a `max`, raising `slow_weight` can only *increase* sigma and shrink exposure. It fails safe.)

Fix: `floor_annualized: float = Field(default=0.05, gt=0.0)`, or pin to `Literal[0.05]` for v1.

### 9. `src/amat/domain/positions.py:34` (and bars.py:51, fills.py:58/116, orders.py:70, instruments.py:32/50) — `parse_symbol` is never called by any domain record
`Symbol = NewType("Symbol", str)` is erased at runtime, and `parse_symbol` (types.py:70) is called only from `config/models.py:60` and `tests/conftest.py:55`. Every domain record accepts an arbitrary string.

Verified by execution: `Position(symbol=' spy ', ...)` constructs; `LedgerSnapshot({' spy ': ..., 'SPY': ...})` passes validation because the key/symbol check (ledgers.py:62-68) compares the key to the record's *own* symbol; result — `holdings_value = 1500` and `weights = {' spy ': 0.667, 'SPY': 0.333}` for one ETF. `Universe.from_clusters` placed the same instrument in two clusters without tripping the exclusivity guard (instruments.py:96), defeating the cluster gross cap.

The invariant is *documented* at bars.py:37 and instruments.py:29 ("Normalized ticker") while every other documented invariant in these records is enforced in `__post_init__`.

Fix: call `parse_symbol` in each record's `__post_init__` (or make `Symbol` a validating value object).

### 10. `src/amat/domain/ledgers.py:50` — `frozen=True` snapshot stores the caller's live mapping
`positions: Mapping[Symbol, Position]` with no defensive copy. Frozen-ness protects the field binding, not the container.

Verified: construct `LedgerSnapshot(2020-01-02, cash=100, positions=d)`, then `d['QQQ'] = Position('QQQ', 5, 50, as_of_session=1999-01-01)` → `equity` goes 1100 → 1350 and the snapshot now contains a position marked in 1999 inside a 2020 snapshot, exactly what ledgers.py:69-75 exists to reject. `holdings_value`, `equity`, `gross_exposure`, and `weights` are all recomputed properties, so every derived figure follows. `reconcile_session` then differences equity values that were never validated in their final form. `Universe.instruments` (instruments.py:77) has the same aliasing on direct construction (the `from_clusters` path is safe).

Fix: `object.__setattr__(self, "positions", MappingProxyType(dict(positions)))` in `__post_init__`; same for `Universe.instruments`. Regression test: mutate the source mapping, assert the snapshot is unchanged.

### 11. `src/amat/domain/bars.py:58,65` — `volume` is exempt from every check applied to prices
`_require_positive_prices` (bars.py:75-95) applies `isinstance(value, Decimal)` and `value.is_finite()` to the five price fields; volume gets only `if self.volume < 0`. Note `source` *is* checked (bars.py:71), so the omission is specific to volume.

Verified: `volume=Decimal('Infinity')` → accepted, `is_tradable=True`. `volume=1000.5` (float) → accepted, stored as float. `volume=5` (int) → accepted. `volume=Decimal('NaN')` → raises `decimal.InvalidOperation`, **not** `DataIntegrityError`, escaping the `AmatError` hierarchy with no symbol or session in the message. Worst case: `volume=float('nan')` → accepted with no error at all (`nan < 0` is `False`), and `is_tradable` returns `False` — a corrupt vendor row silently becomes a permanently untradable session. The class docstring (bars.py:47-48) promises `DataIntegrityError` "on any impossible price or volume relationship".

Fix: add `isinstance(self.volume, Decimal)` and `self.volume.is_finite()` checks before the `< 0` comparison, raising `DataIntegrityError`. Add `nan_volume` and `infinite_volume` rows to `tests/fixtures/invalid_daily_bars.csv` (currently only `negative_volume` at line 6).

### 12. `.claude/scripts/quality_gate.sh:118` — skipped checks do not affect the exit status
`skip_check` (lines 35-38) increments `SKIP`, which is printed at line 117 and then discarded; only `FAIL > 0` produces exit 1.

Reproduced on this machine: `[SKIP] Mypy: not available in the locked environment` even though `./.venv/bin/mypy` exists and reports 9 errors. Cause: `has_uv_tool` (line 41) runs `uv run --no-sync mypy --version`, which fails here (`Could not acquire lock ... Read-only file system`), and the `command -v mypy` fallback (line 78) misses the venv-only binary. The same double-miss applies to ruff, pytest, and pyright. With a degraded uv and no PATH tools, all four lint/type/test checks are skipped and the gate can exit 0.

Mitigation that keeps this at medium rather than high: `validate_bundle.py`, `scan_repository.py`, and `compileall` invoke `python3` directly and always run.

Fix: `if [[ "$FAIL" -gt 0 || "$SKIP" -gt 0 ]]; then exit 1; fi`, plus add `./.venv/bin/<tool>` to the resolution order before the bare-PATH fallback.

### 13. `.claude/scripts/quality_gate.sh:65` — silent fallback to unpinned system toolchain
When the locked environment is unusable, the script runs whatever `ruff`/`mypy`/`pytest`/`pyright` are on PATH (lines 65-67, 78-83, 91-92, 110-111) with no warning, no version capture, and no manifest record.

Measured divergence: locked ruff 0.16.2 (uv.lock:583) vs system 0.15.5; locked pytest 9.1.1 vs `/usr/bin/pytest` 9.0.3; locked mypy 2.3.0 with no system mypy at all. On this run the lint verdict came from `/home/supasuge/.local/bin/ruff`. Additionally the skip message is factually false — it says the tool is "not available in the locked environment" when `.venv/bin/mypy` is present and simply never tried. This contradicts `.claude/rules/00-core.md` reproducibility and CLAUDE.md's documented `uv run ...` commands.

Fix: prefer `.venv/bin/<tool>`; on any fallback, print an explicit warning with `<tool> --version` and count it as a failure in `full` mode.

### 14. `src/amat/config/models.py:356` — `_require_feasible_caps` rejects legitimate configurations
`if reachable < cluster.gross_cap` treats a non-binding cluster cap as infeasible. Verified: `ClusterSpec(name="a", gross_cap=0.5, symbols=("SPY",))` is rejected. `strategy-contract.md:61-63` specifies caps applied *in sequence* and imposes no reachability requirement — models.py:201-202 says so itself. Real consequence: the canonical config loads, but tightening `max_symbol_weight` to 0.10 for a sensitivity run makes the unmodified canonical universe unloadable ("cluster 'us_equity' caps gross at 0.4000 but its 3 symbols can reach only 0.3000"), and constraint sensitivity is a named validation component (architecture.md:34). Fails loud with a precise message; impact confined to authoring alternate configs. **Fix:** delete the per-cluster reachability check; keep the sum check at line 348.

### 15. `src/amat/config/models.py:235` — execution window and timezone are unvalidated
`timezone: str` and bare `dt.time` fields sit beside `Literal`-pinned `price_method`/`price_basis`/`missing_bar_policy`. Verified: `timezone="Mars/Olympus"` and `timezone=""` are accepted; a 15:55–16:00 window and a 09:30–23:59 window both pass (`_require_ordered_window` only checks `start < end`). An invalid IANA string surfaces only when a downstream `ZoneInfo` call raises — the system still fails closed, just after the run has started rather than at the config boundary guardrail 9 designates. Note `strategy-contract.md:13` sanctions a *configured* window, so configurability itself is fine; the gap is the absence of validation. **Fix:** validate the timezone via `zoneinfo.ZoneInfo` in a field validator and bound the window duration.

### 16. `src/amat/config/models.py:266` — cost-stress ladder is not enforced
`if not any(value > self.baseline_one_way_bps ...)` requires only one upward stress. Verified: `stress_one_way_bps=(3.0,)` with `baseline=2.0` is accepted, though `strategy-contract.md:76` requires 0/4/6/10 bps, `validation-protocol.md:38` requires baseline/2x/3x/5x, and `promotion-gates.md:24` requires a result under triple baseline costs. A config that cannot satisfy the protocol validates cleanly and fails only at the promotion gate. (The claim that `amat_v1.toml:169` misdescribes its own values is **refuted** — 4/6/10 are exactly 2x/3x/5x of baseline 2.0, and 0.0 is the diagnostic run the same comment block calls out.) **Fix:** require `{2x, 3x, 5x} ⊆ stress_one_way_bps`.

### 17. `src/amat/config/models.py:150` — trend annualization has no machine-readable home
The `TrendConfig` docstring references an `annualization` term the class does not own; the 252 in `z[i,h] = clip(r[i,h]/(sigma[i]*sqrt(h/252)), -2, 2)` (contract:36) must be borrowed from `VolatilityConfig.annualization_sessions` (models.py:127) or `CovarianceConfig.annualization_sessions` (models.py:195). Those two are independent with no cross-validator: `volatility=252, covariance=12` validates, mis-scaling `w = q*0.08/forecast_vol` by ≈4.6x with no error. Purely latent (all four shipped values are 252), but the undocumented home makes "borrow the covariance one" a plausible implementer choice. **Fix:** hoist a single `annualization_sessions` onto `StrategyConfig`, or add a validator requiring all bases equal.

### 18. `src/amat/domain/ledgers.py:181` — `reconcile_session` checks ordering, not adjacency
Docstring (ledgers.py:174-175) promises to raise "if the snapshots are not consecutive in time"; the code is `if current.session_date <= previous.session_date`. Verified: a 2020-01-02 → 2025-01-03 pair with zero attribution reconciles with residual 0 — five years of fills, fees, and distributions declared fully explained. `validation-protocol.md:10` requires reconciliation "every session". The signature takes no session calendar, so adjacency is not checkable as written. **Fix:** either correct the docstring to "strictly ordered", or add a calendar parameter and enforce adjacency.

### 19. `src/amat/domain/ledgers.py:195` — the accounting-identity error text over-claims
The `AccountingError` message asserts "Every position change requires a fill or a corporate action," but `reconcile_session` never inspects `previous.positions` vs `current.positions`. Previous `{SPY: 100 @ 100}` and current `{SPY: 50 @ 100, QQQ: 50 @ 100}` both at zero cash reconcile with residual 0 — 50 shares destroyed and 50 conjured with no fill. `Position` also carries none of the event identifiers its module docstring (positions.py:3-5) promises, so no caller could perform the trace even if it wanted to. Guardrail 6 has no runtime enforcement anywhere in the domain package. **Fix:** add fill/action provenance ids to `Position` and a per-symbol quantity-delta trace, or correct positions.py:3-5, fills.py:3-5, and ledgers.py:195 to state what is actually verified.

### 20. `src/amat/domain/ledgers.py:178` — tolerance guard misses non-finite values
`if not isinstance(tolerance, Decimal) or tolerance < 0` has no `is_finite()` check, unlike ledgers.py:56, ledgers.py:134, and bars.py:90. Verified: `tolerance=Decimal('Infinity')` returns residual 998999 and raises nothing — a $998,999 unexplained equity change reported as reconciled; `Decimal('NaN')` raises `InvalidOperation` instead of `ConfigurationError`. Caller-supplied only, and the default `DEFAULT_TOLERANCE = CASH_QUANTUM` is safe. **Fix:** `if not isinstance(tolerance, Decimal) or not tolerance.is_finite() or tolerance < 0` (finiteness ordered first so NaN never reaches `< 0`).

### 21. `src/amat/paths.py:170` — `ensure_writable` is check-then-return (TOCTOU)
The approved path is returned for the caller to open later, with no dir-fd handle and no `O_NOFOLLOW`. Verified: `ensure_writable(root, 'outputs/runs/link/x.json')` approves the path while `link` does not exist; creating `outputs/runs/link -> data/raw` afterwards makes a later `open()` land under the immutable raw-data root. Important correction to the original claim: a **pre-existing** symlink *is* caught (`Path.resolve()` follows it and the guard raises), so this requires mutation strictly inside the check→open window, not carelessness. No callers exist today (`grep` finds only paths.py itself and README prose). **Fix:** re-validate immediately before open, or return an opened handle / use `O_NOFOLLOW` on the final component.

Separately: `ensure_writable`'s docstring (paths.py:166-167) promises to raise if the target "already exists there," but the body contains no existence check.

### 22. `src/amat/cli/main.py:54` — the live-trading refusal fails open
`_ENABLED_VALUES = {"1","true","yes","on"}` allowlists the *bad* values, inverting the shape of the adjacent mode check (`_PERMITTED_MODES` at main.py:37-49, deny-by-default). `AMAT_LIVE_TRADING_ENABLED=enabled` (or `2`, `y`) passes silently, contradicting the docstring's promise that "a mis-set variable is caught loudly." (`"TRUE "` *is* caught — `.strip().lower()` normalizes it.) The same function concedes this is defence-in-depth with no execution path to enable, so nothing is actually unlocked; the loss is the signal. **Fix:** `_DISABLED_VALUES = frozenset({"", "0", "false", "no", "off"})` with `if live not in _DISABLED_VALUES:`, plus a regression test.

### 23. `src/amat/paths.py:151` — `is_immutable_path` is a predicate that raises
Annotated `-> bool` with no `Raises:` section, unlike both siblings in the module — but it delegates to `resolve_within`, so an out-of-root candidate raises `ImmutableArtifactError('path escapes the repository root')`, an error type that misdescribes a containment query. Note the raise is the *safe* behavior: returning `False` would make `ensure_writable` permit writes into a symlinked `data/raw`. **Fix:** document `Raises:` on line 152 rather than changing the behavior.

## What is verifiably sound

I read these in full and could not break them. This list is short on purpose.

- **`src/amat/errors.py` (all 67 lines).** Single-rooted hierarchy under `AmatError`, six leaf types, each docstring naming the concrete invariant it guards. `__all__` is complete and sorted. The only defects found elsewhere involving errors are *bypasses* of this taxonomy (NaN volume, NaN tolerance, `TimeoutExpired`), never a flaw in the taxonomy itself.

- **`src/amat/domain/types.py:70-83` — `parse_symbol`.** Correct: type-checks the input, strips and upper-cases, full-matches `^[A-Z][A-Z0-9]{0,9}(?:\.[A-Z]{1,3})?$`, raises `DataIntegrityError` with the offending value. The defect in finding #9 is that nothing calls it — the function is right.

- **`src/amat/domain/types.py:1-15` — the numeric policy docstring.** The Decimal/float split (exact for cash, shares, execution and valuation prices; float for returns, vols, correlations, weights) is stated with an explicit one-directional boundary, and the `Cash`/`Price`/`Quantity`/`Weight` aliases match it. This is the correct treatment per `.claude/rules/10-python.md`.

- **`src/amat/domain/orders.py:77-96` — `SimulatedOrder.__post_init__` causality check.** `execution_session <= signal_session` raises `CausalityError` with both dates and the phrase "same-session execution is a look-ahead defect". This is the sharpest anti-look-ahead guard in the codebase and it is correct. (The separate `side` defect at line 101 is finding #1, not a flaw in this check.)

- **`src/amat/config/loading.py` (all 98 lines).** Digests the raw bytes *before* parsing, so the hash is of the literal source text; distinguishes `TOMLDecodeError`, `FileNotFoundError`, and `OSError`/`UnicodeDecodeError` into separate messages; flattens pydantic `ValidationError` into a readable `loc: msg` list; always chains with `from exc`; and returns source path plus digest as an immutable `ResolvedConfig`. No fallback path, no silent default. Clean.

- **`src/amat/domain/instruments.py:79-109` — `Universe.from_clusters`.** Exclusive cluster membership is enforced with a `seen` map that names *both* colliding clusters in the error. `Universe.symbols` (line 112) preserves cluster declaration order, giving the deterministic matrix column order the docstring promises. `Cluster.__post_init__` (lines 52-64) checks non-empty name, `0 < gross_cap <= 1`, non-empty symbols, and no duplicates. - **`src/amat/paths.py:131-148` — `resolve_within`.** Correctly resolves relative candidates against the root, `.resolve()`s to defeat both `..` traversal and symlinks, and tests `resolved_target != root and root not in resolved_target.parents` — which is the right containment predicate (a naive `str.startswith` would admit a sibling `root-evil/`).
